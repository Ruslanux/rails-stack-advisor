SSR vs CSR vs SSG

Где именно собирается HTML — определяющий выбор, от него зависят SEO, скорость первого экрана и вся структура фронтенда.

SSRCSRSSG
Где рендерится HTML На сервере при каждом запросеВ браузере из пустого HTML + JSНа сборке, один раз
Первый экран Быстро — HTML готовМедленно — сначала грузится JSМгновенно — файл с CDN
SEO ОтличноТребует SSR-прослойки или пререндераИдеально
Персонализация ЛюбаяЛюбаяТолько на клиенте через API
Данные в реальном времени Turbo Streams / WebSocketРодная территорияНевозможно без внешнего сервиса
Стоимость хостинга СерверСервер для API + статикаБесплатно (GitHub Pages)
В Rails это ERB/Phlex + Hotwire — дефолтRails API + React/VueJekyll, Bridgetown, Nanoc
Вердикт. Для Rails по умолчанию берите SSR + Hotwire. CSR оправдан только при клиентском приложении с богатым состоянием. SSG — для контента без пользовательских данных (эта страница именно такая).

Solid Trifecta vs Redis + Sidekiq

Rails 8 сделал ставку на базу данных вместо Redis. Разбираемся, где эта ставка выигрывает, а где нет.

Solid TrifectaSidekiq + Redis
Хранилище Ваша БД (PostgreSQL/SQLite/MySQL)Redis
Сервисов в проде 0 дополнительных+1 (Redis: память, персистентность, мониторинг)
Пропускная способность Тысячи задач/минДесятки тысяч задач/мин
Транзакционность Задача ставится в той же транзакции, что и данныеЗадача может стартовать до коммита — нужен after_commit
Отладка Обычный SQL по таблице задачЧерез дашборд и redis-cli
Дашборд mission_control-jobsSidekiq Web (зрелый)
История выполнения Rails 8.1 архивирует задачи вместо удаленияТолько в Pro/Enterprise
Кэш Solid Cache — на диске, объём в десятки ГБ дёшевоRedis — в RAM, объём стоит денег
WebSocket Solid CableRedis pub/sub
Стоимость Ноль сверх уже оплаченной БД$10–100+/мес за managed Redis
Когда выбирать До ~50 тыс. активных пользователей, один-два сервераПиковые нагрузки, сложные ретраи, троттлинг, уникальность задач
Вердикт. Начинайте с Solid Trifecta — она дефолт в Rails 8 и снимает целый сервис из эксплуатации. Переезжайте на Sidekiq, когда очередь начнёт конкурировать с вебом за ресурсы БД, а не «на всякий случай».

Вердикт. Соло и небольшие команды — Minitest: он уже есть и быстрее. Команда от 5 человек, сложный домен или требования к отчётности — RSpec. Главная ошибка — не выбор фреймворка, а отсутствие тестов вообще.

Формат JSON поверх HTTPJSON, один эндпоинтProtobuf, бинарный

HTTP-кэширование Работает штатноПрактически нетНет
Over-fetching Есть — клиент берёт лишнееНет — клиент выбирает поляНет — контракт жёсткий

Вердикт. REST по умолчанию. GraphQL — когда несколько независимых клиентов просят разные срезы одних данных. gRPC — только для сервис-сервис обмена, и почти никогда как первый выбор в Rails.
