# Rails Stack Advisor

Статическое веб-приложение, которое по описанию проекта подбирает стек, архитектуру
и конфигурацию для Ruby on Rails 8 — с обоснованием каждого решения, командами для
старта и планом реализации по фазам.

**Хостинг:** Jekyll на GitHub Pages, бесплатно.

## Что внутри

| Раздел | Что делает |
| --- | --- |
| `/` | Подборщик: 12 вопросов о проекте → рекомендация по 20 слоям решений |
| `/compare/` | 12 сравнений лоб в лоб с вердиктом по каждому |
| `/projects/` | 7 реальных production-проектов: стек, масштаб, извлечённые уроки |
| `/checklist/` | Чек-лист готовности к продакшену |
| `/glossary/` | Словарь терминов |

Подборщик выдаёт:

- вердикт одной строкой и сводку по ключевым слоям;
- команду `rails new` с нужными флагами и `bundle add` со списком гемов;
- решение по каждому слою с пометкой уверенности (**уверенно / перевес / спорно**),
  списком причин, плюсов, издержек и раскрываемым списком альтернатив со счётом;
- предупреждения, специфичные для выбранной конфигурации;
- план реализации по фазам с оценкой сроков под выбранный горизонт;
- похожие реальные проекты с процентом совпадения профиля;
- экспорт всего отчёта в Markdown, печать в PDF и ссылку на конфигурацию.

## Как устроен движок

Вся логика — данные, а не код. Каждый вариант в `_data/options.yml` имеет базовый вес
и список правил:

```yaml
- id: solid_trifecta
  title: "Solid Trifecta"
  base: 60
  rules:
    - if: { scale: [small, medium] }
      score: 25
      why: "До десятков тысяч задач в сутки БД справляется без отдельного брокера"
    - if: { scale: [huge] }
      score: -25
      why: "Десятки тысяч задач в минуту заметно нагружают основную БД"
```

Балл варианта = `base` + сумма сработавших правил. Побеждает максимум; разрыв со вторым
местом превращается в пометку уверенности. Текст `why` каждого сработавшего правила
показывается пользователю — рекомендация всегда объясняет себя.

Категории считаются в порядке объявления, поэтому правило может опираться на уже
сделанный выбор через `picked:` — так слои остаются согласованными (выбрали Inertia →
ассеты становятся Vite, вьюхи — JSX, публичный API не нужен). Эти кросс-слойные правила
собраны отдельно в `_data/tuning.yml`, чтобы связи между слоями читались в одном месте.

Варианты с `addon: true` не конкурируют за первое место — они включаются в рекомендацию,
если набрали 60 и больше.

## Структура

```
_data/
  questions.yml     анкета: 12 вопросов, 4 секции
  options.yml       92 варианта в 20 категориях с правилами
  tuning.yml        кросс-слойные правила согласованности
  plans.yml         7 фаз, 76 задач с условиями включения
  risks.yml         16 правил-предупреждений
  projects.yml      7 реальных проектов с профилями
  comparisons.yml   12 сравнительных таблиц
assets/js/
  engine.js         чистые функции: данные + ответы → рекомендация
  app.js            рендеринг интерфейса, экспорт, состояние в URL
api/data.json       Liquid отдаёт всю базу знаний одним JSON
script/deploy.sh    локальная сборка + публикация в gh-pages
```

Дополнить базу знаний можно, не трогая код: правится YAML, движок подхватывает.

## Запуск локально

```bash
bundle install
bundle exec jekyll serve
# http://127.0.0.1:4000
```

## Публикация на GitHub Pages

Сайт опубликован из ветки `gh-pages`, куда попадает уже собранная статика:

```bash
script/deploy.sh
```

Скрипт собирает сайт с нужным `baseurl`, кладёт `.nojekyll` и force-push'ит
результат в `gh-pages`. Настройки Pages при этом трогать не надо — они уже
указывают на эту ветку.

> **Почему не через GitHub Actions.** На аккаунте заблокированы Actions
> (`The job was not started because your account is locked due to a billing issue`),
> поэтому workflow не может стартовать даже на публичном репозитории.
> `.github/workflows/pages.yml` лежит на месте и переведён на ручной запуск,
> чтобы не падать на каждом пуше.

### Когда Actions разблокируют

1. Вернуть push-триггер в `.github/workflows/pages.yml` (закомментированный блок в шапке файла).
2. **Settings → Pages → Source: GitHub Actions.**
3. Ветку `gh-pages` можно удалить — она больше не нужна.

После этого сайт будет пересобираться сам на каждый пуш в `main`,
а `baseurl` подставится автоматически.

## Обновление базы знаний

Версии Rails и Ruby, на которые опираются рекомендации, задаются в одном месте —
`_config.yml`, ключ `versions`. Они попадают и в подвал, и в генерируемые команды.
